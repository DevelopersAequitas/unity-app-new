## 1. Catalogue Design Principles & Canonical Payload Contract

**RECOMMENDATION:** Every notification delivered to the Peers Global Leadership App must be **governance-relevant, scope-bounded, deduplicated, and actionable** through the existing `app_notifications` + `user_push_tokens` (`app = 'leader'`) + `[LeaderNotificationDispatcherService.php](file:///c:/Users/malic/OneDrive/Documents/GitHub/unity-app-new/app/Leader/Services/LeaderNotificationDispatcherService.php)` stack:

1. **Zero Consumer Noise:** Timeline likes, comments, chat messages, connection requests, profile views, and daily habit-loop streaks remain excluded (`CONSUMER_EXCLUDED_TYPES`).
2. **Zero Scope Leakage:** A notification must **never** be dispatched to a leader whose active organizational scope (`OrganizationalScopeService` / `LeaderPermissionService::resolveManagedCircles`) does not cover the target `circle_id`, `district_id`, `industry_id`, or `country`.
3. **Standardized FCM & In-App `data` Payload Contract:** Align backend `[LeaderNotificationDispatcherService::dispatchToUser()](file:///c:/Users/malic/OneDrive/Documents/GitHub/unity-app-new/app/Leader/Services/LeaderNotificationDispatcherService.php#L69-L76)` with Flutter's `[NotificationPayload](file:///D:/office%20project/LeaderApp-Fornt-end-/lib/core/notifications/notification_destination.dart#L97-L132)`:
   ```json
   {
     "notification_id": "<uuid>",
     "type": "circle_join_request",
     "category": "circle",
     "priority": "high",
     "route": "/leader-activities",
     "entity_type": "approval",
     "entity_id": "<circle_join_request_uuid>",
     "scope_type": "circle",
     "scope_id": "<circle_uuid>",
     "action_required": true
   }
   ```
4. **Implementation Column Mapping:** Per Prompt §13, the 11th column uses `Existing`, `Partial`, or `Missing`, cross-referenced in Section 3 to the 8 canonical audit labels (`Fully Implemented`, `Partially Implemented`, `Implemented but Incorrect`, `Missing`, `Requires Enhancement`).
